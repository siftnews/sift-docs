# D-035 · 작업 목록 원본 = 이슈 본문 `## TODO`, BACKLOG는 진행 이슈 1개로 축소 (2026-08-04 · D-023 후속 ④ 실행 · D-034 파생)

> [ADR 인덱스](README.md) · 결정 ID: D-035

- **결정**: 태스크 내 하위 단계의 **원본을 GitHub 이슈 본문 `## TODO`로 일원화**한다. `BACKLOG.md`는 **현재 진행 중인 이슈 1개의 구현 단계**만 담고, 완료된 분해는 이슈·PR 링크로 **참조 강등**한다(D-023). 단 되짚을 가치가 있는 기록(e2e가 잡아낸 수집 결함 5건, 회귀 방어 실증 방식, 미반영으로 남긴 것)은 BACKLOG에 압축해 남긴다 — 링크만 남기면 아무도 다시 읽지 않는다.
- **이유**: D-034로 루프 문서 쓰기 주인이 조율 세션이 되면서 **구현 세션이 BACKLOG를 쓸 수 없게 됐다**(권한 deny). 그런데 HARNESS §0.7 절차 3은 "BACKLOG로 분해 → 구현"이었으므로 절차가 성립하지 않는다. 이슈 본문은 조율 세션이 발행 시점에 쓰고 구현 세션이 읽기만 하면 되므로 역할 경계와 자연스럽게 맞는다. 실측 근거도 있다 — #27 이후 7개 태스크는 **BACKLOG 분해가 아예 없는 채로 진행됐다**(2026-08-04 검토에서 발견). 아무도 안 쓰는 이중 장부를 유지하느니 실제로 쓰이는 쪽(이슈)을 원본으로 삼는다. D-023 후속 ④가 이미 같은 방향을 제안해 뒀다.
- **비고**: BACKLOG 폐지가 아니라 축소다 — 진행 중 이슈의 세부 단계는 이슈 본문보다 자주 바뀌므로 작업용 장부가 여전히 쓸모 있다. 구현 세션이 문서에 남길 것이 생기면 `.handoff/notes/`로 조율 세션에 넘긴다(D-034). 이 결정으로 BACKLOG는 122줄 → 75줄로 줄었고, 낡은 섹션 제목(`[PR #24 리뷰 대기]` 등 병합 뒤에도 방치돼 있던 것)이 사라졌다.
