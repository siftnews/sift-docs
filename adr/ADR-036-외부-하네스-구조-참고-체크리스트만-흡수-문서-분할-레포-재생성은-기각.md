# D-036 · 외부 하네스 구조 참고 — 체크리스트만 흡수, 문서 분할·레포 재생성은 기각 (2026-08-04 · 두 논거 정정 → D-037 · 문서 분할 항목 개정 → D-042)

> [ADR 인덱스](README.md) · 결정 ID: D-036

- **결정**: 팀 규모 백엔드 하네스 구조(키워드 트리거 16종 + `workflows`·`checklists`·`references`·`prompts`·`adr` 5분류, 문서 30여 개)를 검토해 **`checklists/`만 신설**한다(`pr.md`·`release.md`). 나머지는 도입하지 않는다. 아울러 **harness.md(237줄)·DECISIONS.md(171줄)는 분할하지 않으며**, 대안으로 검토됐던 «sift-docs·sift-harness 원격 삭제 후 새 레포로 재구성»도 **기각**한다.
- **이유**: ① **없는 것을 문서화하지 않는다** — 트리거 16개 중 6개(Security·Cache/Redis·Messaging/Kafka·Kubernetes·LoadTest·Performance)가 Sift에 존재하지 않고 K8s는 로드맵에도 없다. `build.gradle`에 있는 건 web·modulith·batch·jpa·validation·postgresql·rome 일곱뿐이다. 같은 날 검토에서 **최악의 흠으로 지목된 것이 "존재하지 않는 `.claude/skills/`를 광고하는 README"**였는데, 이 구조를 그대로 깔면 같은 거짓을 30배로 늘린다. 원칙 1·2와 D-029("1개 예시로 굳히면 재작업")에도 정면으로 걸리고, TASKS는 이미 "V2~V4는 미리 확정하지 않는다"를 명문화하고 있다. ② **중복** — `references`·`adr`·`workflows`는 이미 있고(CLAUDE.md·MVP-DESIGN·DECISIONS 35건·HARNESS §0.7), `prompts`는 스킬 박제 태스크로 등록돼 있다. ③ **분할을 안 하는 이유는 별개다** — `§0.7`·`§0.8` 참조가 이미 **33회·10개 파일**에 퍼진 관용구이고, 원본을 5개로 늘리면 D-023("사실마다 원본 1곳")을 스스로 위반한다. 형식만 닮고 원칙을 깨는 셈이다. ④ **레포 재생성 기각** — sift-docs 커밋 **57개(2026-07-09~08-04)**가 곧 상품이고, sift-api·sift-docs README 두 곳이 *"커밋 히스토리 자체가 루프를 실제로 운영한 증거"*라고 적고 있어 지우면 그 서술이 거짓이 된다. sift-harness는 로컬 심링크의 실체이자 private이라 유일한 백업이기도 하다.
- **비고**: 흡수한 것의 핵심은 **CONDITIONAL 분류**다 — REQUIRED(빌드·테스트·정적분석)는 CI가 이미 강제하지만, 조건부 항목은 어디에도 없었다. 일반론이 아니라 **이 프로젝트가 실제로 데인 사례**에서 뽑았다: 정규화 규칙 변경이 기존 키를 무효화해 중복 행을 만든 #37, 시각 의존 결함이 하루 15시간 통과하던 #35, `ddl-auto: update`가 유니크 제약을 소급 생성하지 않는 D-029 실측, 재실행·동시 기동에서 죽던 #21·#39. 나머지 기술의 문서는 **실제 도입 시점에** 만든다(Redis는 V2 캐시, Kafka는 V4, 부하 도구는 M4) — 원칙 2.
