# D-043 · `task-cycle` 상태 기반 전체 개발 사이클 (2026-08-07)

> [ADR 인덱스](README.md) · 결정 ID: D-043

- **결정**: 사용자의 “다음 태스크를 탐색하고 진행하라” 명령은 루트 OMX 세션의 `$task-cycle` 워크플로우로 라우팅한다. 단일 실행 계약은 [`workflows/task-cycle.md`](../workflows/task-cycle.md)이며, 이슈 탐색·확인/생성 → 브랜치 → 설계 → 구현 → 검증 → SSOT → 커밋 → push → PR → CodeRabbit 후속 처리 → `ready` 종료를 순차 수행한다.
- **결정**: 현재 사이클 상태는 `.omx/state/task-cycle.json`에 기록한다. 런타임 상태는 문서 원본이 아니며 세션 복구와 단계 게이트에만 사용한다.
- **결정**: 이슈·feature 브랜치·커밋·feature push·PR 생성과 CodeRabbit actionable 지적 반영은 사용자가 명시한 task-cycle 사이클 범위에서 에이전트가 수행한다. PR merge, main 공개 상태, 배포, 삭제·백필은 사용자 결정 게이트다.
- **결정**: turn-complete 감사 훅은 제거한다. 개별 규칙의 정적 감사보다 상태 기반 단계별 게이트와 각 단계의 원본 명령·출력 증거를 사용한다.
- **결정**: CodeRabbit 지적은 최신 PR head SHA 기준으로 조회한다. 반영 지적은 테스트·커밋·push 후 새 head에서 재검토하며, 반영하지 않는 지적은 근거를 남긴다. 사용자의 명의로 리뷰 답글을 작성하지 않는다.

## 이유

turn-complete 훅은 작업을 시작하거나 이슈·브랜치·PR·리뷰 상태를 소유하지 못해 전체 사이클을 보장하지 못한다. 단계마다 상태와 성공 조건을 갖춘 워크플로우가 재개·실패·외부 서비스 지연을 다루기에 적합하다.

## 관계

- D-034의 역할 런처·권한 프로파일은 현재 OMX 루트 세션 운영으로 대체한다.
- D-033의 “리뷰 지적을 반영하지 않는 경우 사용자 판단”은 task-cycle의 `needs-decision` 게이트로 구체화한다.
