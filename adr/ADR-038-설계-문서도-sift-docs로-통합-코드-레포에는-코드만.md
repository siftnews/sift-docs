# D-038 · 설계 문서도 `sift-docs`로 통합 — 코드 레포에는 코드만 (2026-08-05 · D-021 ① 전면 개정)

> [ADR 인덱스](README.md) · 결정 ID: D-038

- **결정**: `sift-api/docs/`의 **MVP-DESIGN·SELECTION·EVENTS를 `sift-docs/references/`로 이동**하고 `sift-api/docs/`를 폐지한다. 이로써 **모든 문서의 원본이 `sift-docs` 한 곳**이 된다. 부수 조치 셋 — ① 구현 세션 프로파일의 `Edit(sift-docs/**)` 통째 deny를 **막을 것 열거 방식**으로 좁혀 설계 문서는 쓸 수 있게 한다. ② `sift-api/.coderabbit.yaml`의 md 필터를 `!**/*.md`로 원상 복귀(PR #43에서 `docs/`를 리뷰 대상으로 열었으나 그 디렉터리가 사라졌다). ③ `sift-web`이 생겨 `references/`에 두 레포 문서가 섞이면 그때 하위 디렉터리로 나눈다 — 지금 미리 쪼개면 빈 껍데기다.
- **이유**: 사용자 결정(2026-08-05). **공개 문서 레포 하나가 진입점이 된다** — 채용 심사자도 냉시작하는 세션도 한 곳에서 시작하면 되고, 코드 레포에는 코드만 남는다. D-021이 설계 문서를 코드 레포에 둔 근거("구조 변경 PR에서 코드와 같은 diff로 리뷰")는 **실제로 작동하고 있었다** — `src/`와 `docs/`를 같은 커밋에서 고친 것이 7건(`67d4348`·`40463a5`·`24dfdc6`·`1fe4a03`·`485e9ed`·`e366fff`·`b7e403e`). 그럼에도 진입점 분산의 비용을 더 크게 본 판단이다.
- **비고 — 잃은 것과 방어책**: ① **같은 diff 리뷰 불가(복구 불가)** — 크로스 레포 diff는 CodeRabbit도 사람도 볼 수 없다. 바로 전날 PR #43이 연 `docs/` 리뷰 경로가 무의미해져 필터를 되돌렸다. ② **원자성 상실(복구 불가)** — 코드+문서가 두 레포·두 커밋으로 갈라져 **한쪽 push 누락이 곧 drift**다. [PR 체크리스트](../checklists/pr.md) CONDITIONAL에 두 레포 확인을 명문화해 방어한다. ③ `sift-docs`는 main 직접 커밋 레포(D-024)라 **설계 문서가 리뷰 없이 들어간다** — sift-docs를 이슈·PR 흐름으로 바꿀지는 **미결**. ④ **권한 규칙 형태가 바뀐 이유**: `deny > allow`라 "전체 deny + 예외 allow"가 성립하지 않으므로(D-034에서 확인) 막을 것을 **열거**한다 — 루프 3종 + README + `adr/`·`roles/`·`checklists/` + HARNESS·PLAN. `references/`에 새로 생기는 파일은 기본 허용인데, 거기가 설계 문서 자리이므로 의도된 동작이다. ⑤ **파일 이력은 따라오지 않는다** — 레포가 달라 `git mv`가 불가능하다. 과거 커밋은 `sift-api` 로그에 남는다(D-036이 지킨 "커밋 히스토리가 곧 증거"는 훼손되지 않는다). ⑥ **부수 발견**: Java javadoc 2곳(`content/package-info.java`·`content/domain/Topic.java`)이 `docs/selection.md`를 상대 경로로 참조하고 있어 절대 URL로 함께 고쳤다 — 이동만 하고 놓쳤으면 죽은 참조가 됐다.
