# 협업 및 에이전트 운영 규칙

## 실행 위치
- 일반 작업 세션은 비-Git 워크스페이스 루트 `siftnews/`에서 시작한다.
- Git·빌드·테스트 명령은 대상 하위 저장소(`sift-api`, `sift-docs`)에서 실행한다.

## 책임
- **주 작업 에이전트**: 오케스트레이터로서 범위 확정, 하위 작업 배분, 결과 통합, 최종 검증을 책임진다.
- **탐색·검토 역할**: 독립적인 사실 조사, 설계·테스트·보안·성능 검토를 수행하고 근거를 보고한다.
- **사용자**: 설계 분기와 외부·파괴적 작업의 최종 결정을 내린다.

## 병렬화
- 독립적이고 읽기 전용인 탐색·검토는 OMX로 병렬화할 수 있다.
- 하나의 기능 변경처럼 순차 의존이 큰 구현은 한 소유자가 끝까지 수행한다.
- 공유 파일을 동시에 수정하지 않는다. 병렬 구현이 불가피하면 대상 하위 저장소에서 worktree와 파일 소유권을 분리한다.

## OMX 운영
- 단발성이고 독립적인 조사에는 필요한 역할만 배정한다. 병렬화 비용이 이득보다 크면 주 세션이 직접 수행한다.
- Team 실행 전 대상 저장소의 `git status --short`를 확인하고 기존 사용자 변경을 보호한다.
- Team을 사용한 경우 주 세션은 상태와 작업 증거를 확인하고, 모든 작업이 terminal 상태가 된 뒤 종료한다.
- 워커 결과는 그대로 채택하지 않고 주 세션이 원본 파일·테스트·명령 출력으로 재검증한다.

## Graphify
- Graphify 인덱스는 `sift-api/graphify-out/`만 사용한다. `sift-docs`에는 그래프와 Graphify Git 훅을 만들지 않는다.
- 기존 그래프가 있으면 코드베이스 질문 전에 query/path/explain으로 먼저 확인한다.
- `sift-api` 코드 변경 뒤에는 Graphify 갱신 상태를 확인하되, 그래프는 원본이 아닌 파생 인덱스로 취급한다.

## 보고 형식
검토 결과에는 범위, 파일·위치, 근거, 위험도, 최소 수정안, 필요한 검증을 포함한다. 설계 결정이 필요한 경우에는 구현을 추정으로 진행하지 않고 사용자에게 선택지를 보고한다.
