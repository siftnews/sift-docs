# PR 생성 워크플로우

1. 변경 범위와 완료 조건을 이슈 또는 작업 설명과 대조한다.
2. [PR 체크리스트](../checklists/pr.md)의 REQUIRED와 해당 CONDITIONAL 항목을 완료한다.
3. 코드·설계 문서·다이어그램이 함께 바뀌어야 하는지 확인한다.
4. 제목은 연결 이슈 제목을 **문자 단위까지 그대로** 사용한다. PR 제목에 별도의 `{type}:` 형식을 적용하지 않는다. 본문은 PR 템플릿의 `close #이슈번호`와 `Check list`를 유지한 채 배경·변경 내용·검증 결과·롤백 정보를 적는다.
5. 생성 시 `--assignee chltjsdl0119`와 작업 유형에 맞는 `--label`을 함께 지정한다. 라벨 매핑은 이슈와 동일하게 `feature`·`bug`·`chore`를 사용한다. **기본 생성 명령에 `--draft`를 넣지 않는다.** 사용자가 초안을 명시적으로 요청한 경우에만 draft PR을 만든다.
6. 생성 직후 `gh pr view`로 제목과 연결 이슈 제목의 완전 일치, 연결 이슈, Check list, Assignees, Label, base branch(`develop`), head branch, Ready for review 상태, CI와 CodeRabbit 상태를 확인한다. 하나라도 누락·불일치하면 리뷰 요청 전에 보정한다.
7. CodeRabbit이 설정된 저장소에서는 현재 세션이 **Review Monitor**로 전환된다. CodeRabbit의 현재 PR head SHA 대상 리뷰 제출과 인라인 댓글을 감시하고, 리뷰가 도착할 때까지 PR 사이클을 완료로 선언하지 않는다. 리뷰가 지연되거나 실패하면 그 상태를 사용자에게 보고한다.
8. Review Monitor가 수집한 지적은 현재 코드·설계·테스트와 대조해 수용·기각·추가 확인 필요로 분류한다. 사용자가 “다음 태스크를 탐색하고 진행하라” 사이클을 위임한 경우 수용 지적은 테스트·커밋·push까지 자동 반영한다.
9. 독립 검토가 필요한 위험과 미해결 사항을 명시한다.

## Review Monitor

- 감시 대상은 현재 세션이 생성한 Ready for review PR 하나이며, 별도 상시 서비스나 외부 알림 채널은 사용하지 않는다.
- `coderabbitai`의 리뷰 제출과 인라인 댓글을 수집한다. Draft 안내·리뷰 skip·도움말 같은 상태 댓글은 지적에서 제외한다.
- 리뷰 제출 뒤에는 현재 PR의 **최신 head SHA**에 속한 미해결 스레드를 전체 조회한다. 이전 head SHA의 지적은 재검토 대상이 아니다.
- 인라인 댓글이 모두 도착할 시간을 짧게 확보한 뒤 한 번에 검토한다. 댓글마다 별도 보고하거나 같은 리뷰를 중복 처리하지 않는다.
- CI 결과도 함께 수집해 통합 보고에 포함한다.
- 통합 보고 후 리뷰 후속 처리 절차를 시작한다. 위임된 task-cycle 사이클에서는 수용 지적을 바로 반영하고, `needs-decision`만 사용자 게이트로 남긴다.

## 리뷰 후속 처리

1. Review Monitor의 통합 보고 뒤, 리뷰 스레드별로 현재 코드와 요구사항을 다시 대조해 반영·미반영을 판정한다.
2. 반영한 변경은 관련 테스트를 실행한 뒤 커밋·푸시하고, PR head SHA가 해당 커밋인지 확인한다.
3. 미반영은 근거를 리뷰 스레드에 남긴다.
4. 원격 반영 또는 근거 기록이 끝난 스레드만 GitHub에서 resolve하고, 미결정·미검증 스레드는 열린 상태로 둔다.

병합, 공개 상태 변경, 외부 시스템 변경은 사용자 게이트다.
