# PR 체크리스트

## ■ REQUIRED
- [ ] 변경 범위와 완료 조건을 충족했다.
- [ ] 빌드 성공, 전체 테스트 통과, 컴파일 오류 없음.
- [ ] 포맷 적용 및 정적 분석 통과.
- [ ] public 인터페이스·DTO·enum이 별도 파일이며, 중첩 DTO·인라인 선언이 없다.
- [ ] REST 경로가 `/api/v{major}`이고 API 설계 문서와 일치한다.
- [ ] 테스트 범위와 실행 결과를 PR에 기록했다.
- [ ] 구조·계약 변경에 필요한 설계 문서를 갱신했다.
- [ ] PR 템플릿의 `close #이슈번호`와 Check list를 유지했다.
- [ ] PR 제목이 연결 이슈 제목과 문자 단위까지 일치한다.
- [ ] Assignees(`chltjsdl0119`)와 작업 유형 Label을 지정했다.
- [ ] 사용자가 초안을 명시하지 않았다면 `--draft` 없이 PR을 생성했고 Ready for review 상태다.
- [ ] base branch가 `develop`이고 CI와 CodeRabbit 상태를 확인했다.
- [ ] 반영한 리뷰 변경은 검증·커밋·푸시 뒤 PR head에 포함됐음을 확인했고, 그 뒤 스레드를 resolve했다.
- [ ] 미반영 리뷰는 근거를 스레드에 남긴 뒤 resolve했으며, 미결정·미검증 스레드는 열어 두었다.

## □ OPTIONAL
- [ ] 성능 벤치마크 또는 부하 테스트 결과를 기록했다.
- [ ] 아키텍처·의존성 검토 결과를 기록했다.

## ◇ CONDITIONAL
- [ ] 스키마 변경: 마이그레이션, 기존 데이터, 인덱스·제약, 롤백을 검토했다.
- [ ] 캐시 변경: 키·TTL·무효화·장애 시 동작을 검토했다.
- [ ] API 변경: 호환성·버전·오류 계약·보안 영향을 검토했다.
- [ ] 메시지 변경: 계약 호환성·재처리·멱등성을 검토했다.
- [ ] 배포 가능 변경: 관측·알림·롤백 절차를 준비했다.
