# 작업 설계 체크리스트

- [ ] 작업 유형과 영향 범위를 판정했다.
- [ ] 세션과 명령의 실행 위치가 `siftnews/` 루트 및 대상 하위 저장소 규칙과 맞다.
- [ ] 공통 사전 문서와 영향 영역 설계를 읽었다.
- [ ] 구현 범위, 완료 조건, 필수·조건부 검증을 정했다.
- [ ] 독립적인 탐색·검토만 병렬화했다.
- [ ] OMX Team을 사용한다면 대상 저장소의 기존 변경과 worktree·파일 소유권을 확인했다.
- [ ] `sift-api` 관련 광범위한 탐색이라면 기존 Graphify 그래프와 최신성을 확인했다.
- [ ] 설계 분기·파괴적 작업을 사용자에게 보고했다.
- [ ] 문서, 테스트, 릴리스 산출물의 갱신 대상을 정리했다.
